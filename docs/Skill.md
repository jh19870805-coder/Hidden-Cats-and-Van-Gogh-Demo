# 游戏制作 Skill（必读）

> **用途**：这是团队（你 + 我）在本项目里制作任何需求时的“工作协议 + 操作手册”。  
> **强制要求**：**每个需求**开始前必须阅读本文档；并且在开始制作前必须阅读文档2与文档3。  
> - 文档2：`docs/DevelopmentOrderRecommendation.md`（功能优先级 & 当前状态）  
> - 文档3：`docs/FeatureSpec.md`（功能说明 / 功能策划案 / 系统拆分）

## 1. 需求处理总规则（强制）

- **每个新需求必须走三步**：
  - **读文档1**：确认制作方式、风险边界、DOD/回写规则。
  - **读文档2**：确认当前阶段、依赖、优先级是否冲突。
  - **读文档3**：确认系统归属、数据口径、UI/交互规则、配置方式。

- **验收回写（强制）**：当一个需求“完成并且被你接受”后，我必须同步更新：
  - **文档2**：把对应条目状态改为 ✅/⚠️，写清“已完成内容 + 残留事项”。
  - **文档3**：把对应系统章节更新为“当前实现事实”（接口、配置路径、行为变化）。

## 3. Definition of Ready（开始写代码之前必须满足）

- **已确认系统归属**：这个需求属于文档3里的哪个系统（或新增系统）。
- **已确认依赖**：
  - 需要 `CollectionService` / `WindowManager` / `SettingsManager` 等管理器吗？
  - 需要哪些 Prefab/场景节点存在并正确挂载吗（尤其是 StartUp）？
- **已确认数据口径**：是“单场景计数”还是“全局计数”，以及“总数从哪里来”。
- **已确认最小可用版本（MVP）**：先跑通流程，再做美化/扩展（避免大返工）。

## 4. Definition of Done（完成一个需求的最低标准）

- **功能可用**：按“验收标准”走一遍，结果稳定。
- **不会破坏存档**：
  - 需要持久化的内容能正确保存/读取。
  - 重置流程（`GameProgressResetService`）不会把设置也清掉（除非需求明确）。
- **不会破坏窗口流**：`WindowManager` 切窗、弹窗遮罩、返回路径正常。
- **日志策略合理**：默认不刷屏；Debug 日志只在 `enableDebugLog` 开启时输出。
- **二次定位必备日志（强制）**：如果我第一次修 bug 没改对，那么第二次必须用日志辅助定位问题，并且我必须明确告诉你“在哪个脚本/哪个位置打开日志、怎么打开”。建议优先用以下方式之一（按易用度排序）：
  - **Inspector 开关**：脚本上提供 `[SerializeField] private bool enableDebugLog;`，并在关键路径用 `if (enableDebugLog) Debug.Log(...)` 输出。
  - **PlayerPrefs 开关**：提供 `PlayerPrefs.GetInt("HC_DEBUG_xxx", 0) == 1` 控制，并在 Skill/文档里写清 Key 和如何设置。
  - **编译宏开关**：用 `#if HC_DEBUG_xxx` 包裹 Debug.Log，并在 Unity 的 `Scripting Define Symbols` 里说明要加的宏名。
- **文档回写完成（如果你验收通过）**：更新文档2、文档3。
- **通用封装方法已归档**：如果这次改动里新增/调整了可复用的小组件或通用方法（例如各种通用 UI 组件、工具脚本等），并且需要放入 `docs/ReusableUtils`：
  - 在 `docs/ReusableUtils/Readme.md` 里新增对应小节，写清**适用场景 + 使用步骤 + 示例代码**；
  - 把对应脚本复制一份到 `docs/ReusableUtils/` 目录下，作为“脚本原件备份”（命名与类名保持一致，如 `SimpleBubbleHint.cs`）。

## 5. Unity 工程实践（本项目约定）

### 5.1 管理器与启动（最常见坑）

- **单例管理器**（如 `CollectionService` / `SettingsManager` / `AudioManager` / `CursorManager`）必须通过 `StartUp` 流程确保存在。
- `GameInitializer` 的职责是“确保关键管理器存在并正确初始化”。  
  - 如果出现 `CollectionService.Instance == null`，优先检查 **StartUp 是否挂了 `GameInitializer`**（以及是否有重复实例被销毁）。

### 5.2 数据口径（计数系统）

- **单场景计数**：`CollectionService.GetSceneCount(sceneName, type)`  
- **全局计数**：`CollectionService.GetGlobalCount(type)`  
- “总数/上限”的来源必须明确：通常来自 **扫描当前已加载的窗口 Prefab 的 interactables**，或未来的 **StageConfig**。

### 5.3 Prefab / 节点约定

- 尽量**不写死层级路径**；如必须写死，提供 Inspector 字段并提供兜底查找（如 `MainCatClickHandler` 的做法）。
- 通用 UI（提示/对话框）优先使用统一服务（见文档3），避免每个脚本各写一套。

- **把条目从**：❌/⚠️ → ✅（或 ⚠️）

  - **已知限制**：哪些仍是占位/需要后续优化。
  - **下一步**：如果还有后续子任务，拆成更小的可执行条目。

### 6.2 更新文档3（系统功能说明）

- 更新对应系统章节里的：
  - **对外接口**（public API / 事件）
  - **配置方式**（Inspector 字段、Prefab 位置、ScriptableObject）
  - **数据保存**（存档 Key / 结构）
  - **边界规则**（例如解锁判定、总数计算、跨窗口/跨场景行为）
